# 미결 설계 항목

이 문서는 구현 전에 확정해야 하는 큰 단위의 설계 항목을 관리한다. 미정인
내용을 코드나 DB 스키마로 먼저 고정하지 않는다.

## 1. PersonProfile 등록 업무 흐름

다음 기본 흐름은 확정했다.

1. `EXTERNAL`로 확정되기 전에는 등록을 묻지 않는다. 확정 때까지 이미 저장된 표본이
   등록 정책의 고품질·자세 다양성 조건을 충족할 때만 등록을 묻는다. 조건이 부족하면
   해당 ObservationSession에는 등록을 묻지 않는다.
2. 조건을 충족하면 ObservationSession당 한 번 `RegistrationProposal`을 만든다.
3. 응답 채널에서 이름을 직접 받는다. 빈 입력이면 해당 세션에는 다시 묻지 않는다.
4. 이름이 입력되면 프로필을 생성한 뒤 선택된 표본의 임베딩을 템플릿으로
   추가한다.
5. 검색 대상 반영 뒤 새 ObservationSession부터 새 템플릿으로 등록 인물을 검색한다.

등록 응답 채널은 공통 등록 유스케이스의 입력 경계다.

| 채널 | 용도 | 응답 방식 |
| --- | --- | --- |
| Terminal | 개발·현장 확인 | 터미널에서 이름 직접 입력. 빈 입력은 취소 |

Terminal은 `RegistrationResponse`를 등록 Application에 전달한다. 카메라 출력 및
얼굴 분석 작업자는 응답 대기 중에도 계속 동작한다. 외부 알림 채널은 후속 범위다.

아직 확정할 내용:

- 표본 중복 판정의 실제 카메라 보정: `0.98` 임베딩 중복 기준,
  yaw `65도`·pitch `50도`·roll `40도` 품질 기준과 표본 간 `15도` 자세 차이 기준 유효성 확인
- 얼굴 가림 품질 모델은 `models/face_occlusion.onnx`로 추가했다. 얼굴 crop을 입력으로
  가림 확률을 계산하며, 현재 초기 거부 임계값은 `0.50`이다. 실제 카메라에서 맨얼굴·
  마스크·손 가림 표본을 비교해 오탐·미탐 기준을 보정해야 한다. 공개 라벨 예시의 개별
  얼굴에서는 정상 얼굴과 가림 얼굴 출력이 구분되는 것을 확인했지만, 실제 카메라 가림
  표본은 아직 확보하지 못했다.
- 표본 간 최소 시간 간격
- 등록 실패 시 운영자에게 보여줄 결과와 재시도 방식

등록 제안은 생성 뒤 30분 안에 응답해야 한다. 만료 또는 빈 입력 후에는 해당
ObservationSession에 다시 묻지 않는다.

## 2. 데이터 및 DB 설계

기본 보존 범위는 확정했다.

- 원본 카메라 프레임, 품질 미통과 얼굴 crop, 중복 얼굴 후보는 저장하지 않는다.
- FaceCandidate와 임시 임베딩은 메모리에서 품질·중복 평가를 거친다. 통과한 얼굴 crop,
  FaceSample, 임베딩, ObservationSession, IdentityDecision만 영속 저장한다.
- 활성 PersonProfile의 이름과 승인된 얼굴 템플릿을 영속 저장한다.
- Telegram은 현재 범위에서 제외한다.

초기 PostgreSQL DDL과 마이그레이션은 `infrastructure/postgres/migrations`에 정의한다.
물리 보존·배포 운영을 시작하기 전에는 다음을 결정해야 한다.

- 고품질 얼굴 표본·관찰 세션·판단 이력의 보유 기간과 물리 파기 시점
- PostgreSQL과 MinIO의 배포 방식, 인증 정보, 백업·복구 정책
- PostgreSQL과 MinIO 사이 얼굴 crop 저장 실패의 보상 처리 방식

운영 전에는 개인정보 처리의 적법한 근거, 고지·동의 방식, 보유 기간과 파기
절차를 별도 검토해야 한다.

## 3. IdentityPolicy 상세화

다음 구조는 확정했다.

- FaceSample별 `IdentityDecision`은 그 표본의 최상위 PersonProfile 한 건 또는
  활성 템플릿이 없어 검색 후보가 없는 결과를 이력으로 저장한다.
- `IdentityPolicy`는 누적된 고품질·비중복 표본을 평가하며 상태를 보관하지 않는다.
- `IdentityPolicy`는 PersonProfile별 누적 근거를 평가한다. 개별 유사도의 전체 최고값만으로
  현재 인물을 정하지 않는다.
- `ObservationSession.current_identity`가 현재 결과, PersonProfile 참조, 근거
  IdentityDecision 참조를 보관한다.
- 현재 결과는 `ANALYZING`, `IDENTIFIED`, `EXTERNAL`이다.
- 최상위 검색 결과는 이력으로 보존하되, 유사도가 등록 인물 인정 임계값 이상일 때만
  해당 PersonProfile의 근거로 계산한다.
- 같은 PersonProfile의 근거가 비중복 FaceSample 2개 이상이면 `IDENTIFIED`, 등록 인물
  근거가 없는 비중복 FaceSample 3개 이상이면 `EXTERNAL`이다.
- 검색 결과 동점은 유사도 내림차순 뒤 템플릿 ID 오름차순으로 고정 정렬한다. 동점 자체가
  별도 신원 상태를 만들지는 않는다.
- `IDENTIFIED` 또는 `EXTERNAL`이 결정되면 해당 세션의 FaceSample 수집을 중단한다.

아직 확정할 내용:

- 현재 기술 검증값 `0.60`의 실제 카메라·임베딩 모델 기준 보정

## 4. 후속 처리 인터페이스

- 세션 종료 후 알림이 필요한 업무 시나리오
- 알림 내용, 수신자, 재시도와 중복 방지
- 외부 API 또는 운영 화면의 요구사항

## 5. 운영 설계

- 카메라 장치 선택, 재연결, RTSP 지원 범위
- 모델 버전 관리 및 가중치 배포 방식
- 구조화 로그, 모니터링 지표, 장애 대응 기준
- 실행 환경과 배포 방식
